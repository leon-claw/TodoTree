# 桌面任务拆分与执行流程整改实施计划

**目标：** 完成产品整改文档第一批，让用户可以在 Flow 中直接、连续或批量创建任务，并在列表中按重要程度与紧急程度总分排序；本轮追加画布空白点击失焦和编辑自动延迟保存。

**架构：** JSON 任务树仍是唯一业务数据源；树操作集中在 `storage.ts`，Flow 节点调用 `App` 的统一操作，创建先以草稿提交，删除在确认后一次性变更。列表排序只派生叶子视图；Flow 结构变化不重置用户视口，桌面详情面板占用真实布局宽度。

**技术栈：** React 19、TypeScript、现有 `@xyflow/react`、`d3-hierarchy`、Tailwind CSS。

**需求基准：** `docs/product/2026-09-28-product-review-remediation.md` 第 4、5.1、8 节第一批范围。

## 全局约束

- 实现第一批 F01、F02、F03、L01 及创建草稿、完成限制、具名删除确认，并纳入本轮追加的 Flow 空白失焦与统一自动延迟保存；不扩展到其他第二批或待定 P2 项。
- JSON 树继续作为唯一任务数据来源；列表排序不得改写树顺序或完成状态。
- 子任务和同级任务的创建入口共用完成限制；批量创建作为单次树更新。
- 同分按原始树遍历顺序稳定排列；已完成叶子保持可见。
- 不引入依赖，不实现待确认的评分继承，也不扩展到第二批功能。
- 本次不新增或运行测试；按上级工作指令仅进行代码修改和差异审阅。

## 文件职责

- `apps/web/src/storage.ts`：新增有标题的根／子／同级批量创建树操作与后代计数。
- `apps/web/src/App.tsx`：持有创建和删除确认状态，提交单次树操作并协调选择状态。
- `apps/web/src/components/TaskComposer.tsx`：新增可复用的单条／批量标题草稿输入，Flow 节点操作时锚定在节点旁。
- `apps/web/src/types.ts`：定义创建草稿的屏幕锚点类型。
- `apps/web/src/components/TodoNode.tsx`、`treeLayout.ts`、`GraphView.tsx`：节点直接操作、父节点上下文、完成状态、初次适配与视口保持。
- `apps/web/src/components/SettingsPanel.tsx`：标题与分数编辑自动更新应用状态，删除确认使用名称与级联数量；桌面面板进入分栏布局。
- `apps/web/src/components/SettingsPanel.tsx`、`SettingsPage.tsx`：标题、分数及标签名称支持直接编辑并自动提交到应用状态；数据变更在停止操作 700 ms 后写入本地存储，页面离开时刷新待保存数据。
- `apps/web/src/components/GraphView.tsx`：点击 Flow 空白区域清除节点选择并关闭详情面板。
- `apps/web/src/components/ListView.tsx`：稳定总分降序、显示总分和两项分数组成。

## 重点审阅输入

- 批量标题含空行、首尾空白或全空白：预览数量与实际创建数量一致，全空时不写入。
- 中文输入法仍在选词：Enter 不会提前提交。
- 同级任务挂接到当前任务的真实父节点；根任务同级仍然创建在根层。
- 对已完成叶子请求添加子项：鼠标及批量入口均不能绕过共同约束。
- 删除父节点：确认内容包含任务名和后代数量；取消不改变任务树。
- 总分相同及已完成任务：顺序稳定，完成项仍可见。
- Flow 空白画布点击后取消节点选中；节点或画布控件上的点击不误触发失焦。
- 标题、备注、日期、分数、标签、完成状态和标签管理等数据编辑均进入统一的延迟保存；页面离开时补写待保存数据。
