# 递归 Todo Web 应用设计稿

## 目标

构建一个兼容桌面和移动浏览器的本地 Todo Web 应用。用户可以在传统列表中管理可执行任务，也可以在左到右展开的树形图中拆分任务。数据不经过服务器，以 JSON 保存并支持手动导入、导出。

## 已确认的产品范围

- 两种主要视图：经典列表和树形图。树形图中每个节点代表一个 Todo，子 Todo 位于父节点右侧，节点使用一致的卡片样式。
- Todo 可以递归拆分任意层级。只有没有子节点的叶子 Todo 可以标记完成；父节点不可标记。列表只显示所有叶子 Todo，包含已完成和未完成项。
- 点击图表节点打开右侧设置面板。用户可编辑标题、字符串备注、字符串截止日期、重要程度（0–100）、紧急程度（0–100）和多个标签。
- 设置页面提供标签管理和 JSON 导入、导出。标签由名称、颜色组成。
- 所有数据本地保存，不提供账号、服务端存储或自动同步；设备间通过 JSON 文件手动迁移。
- 风格为清爽效率工具。

## 架构

- 使用 pnpm workspace monorepo，第一版只包含 `apps/web`，不预建没有实际用途的共享包或后端。
- Web 技术建议为 React、TypeScript 和 Vite。图表由 `@xyflow/react` 显示自定义 Todo 节点，并提供画布缩放和平移；用适合树结构的布局算法计算节点坐标。可优先复用项目已有依赖；若没有合适的树布局依赖，再采用 `d3-hierarchy` 的 tree layout。
- Todo 的递归 JSON 树是唯一数据源。图表节点、连接线和列表叶子项均从该树派生，避免分别维护多份任务状态。
- 完成状态只保存在叶子节点。新增第一个子节点前，已完成 Todo 必须先恢复为未完成；父节点不带完成状态，新子节点默认未完成。

## 交互与布局

- 顶部可在“列表 / 图表 / 设置”之间切换；提供创建根 Todo 的入口。
- 图表自左向右排列父子关系。点击任意节点打开右侧面板；在面板中编辑字段、添加子 Todo 或删除当前 Todo。
- 叶子 Todo 的完成开关放在设置面板中，避免节点卡片因深度或类型改变样式。列表视图为叶子项提供直接完成开关。
- 已完成叶子不可添加子项；取消完成后才可拆分。删除 Todo 时先确认，并级联删除全部后代。
- 若删除操作使父节点失去最后一个子节点，该节点变成未完成的叶子 Todo。
- 桌面端使用右侧抽屉；移动端使用全屏侧滑面板。移动端列表随屏幕宽度排版，图表支持触控平移和缩放。
- 第一版按树结构自动布置节点；不增加任意连线、拖拽重排、筛选、提醒或同步等未提出的能力。

## 数据与持久化

推荐的最小 JSON 结构：

```json
{
  "formatVersion": 1,
  "todos": [
    {
      "id": "todo-id",
      "title": "任务标题",
      "note": "",
      "dueDate": "",
      "importance": 0,
      "urgency": 0,
      "tagIds": [],
      "completed": false,
      "children": []
    }
  ],
  "tags": [
    { "id": "tag-id", "title": "工作", "color": "#4f7cac" }
  ]
}
```

- `dueDate` 使用 `YYYY-MM-DD` 字符串；备注与无截止日期时用空字符串。重要程度和紧急程度默认 0，且只能是 0–100 的整数。新 Todo 默认无标签、未完成、无子节点。
- 只有叶子 Todo 才有 `completed` 字段；有子节点的 Todo 不显示完成开关。`tagIds` 可包含多个标签 ID。
- 在浏览器本地存储中以 JSON 序列化保存；每次有效修改后更新。本地数据仅属于当前浏览器存储空间。
- 导出生成 JSON 文件。导入先解析并校验版本、字段类型、数值范围、ID 唯一性和标签引用；校验通过后明确确认整体替换。校验失败或用户取消时，保留当前数据不变。

## 错误处理与验收标准

- 空数据、无效 JSON、未知格式版本、无效字段、越界数值或悬空标签引用都有清楚提示；失败导入不覆盖现有数据。
- 本地存储读写失败时提示用户，不能静默丢失修改。
- 刷新页面后，列表、图表、标签与完成状态保持一致。
- 任意深度的拆分都能在图表中反映；父节点从不出现在叶子列表中，也没有完成开关。
- 删除父节点后，其整棵后代树都会消失；删除最后一个子节点后，父节点成为未完成叶子。
- JSON 导出可重新导入；导入前取消或导入非法文件不会更改原数据。

## 需求边界

不实现云端账户、同步、协作、通知、重复任务、复杂过滤/排序、自由连线或拖拽布局。若用户后续提出这些需求，再单独设计。
