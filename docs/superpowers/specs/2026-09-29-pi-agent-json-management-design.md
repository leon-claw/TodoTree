# TodoTree 内置 Pi Agent 管理 JSON：设计规格

日期：2026-09-29
状态：待书面审阅

## 目标与已确认范围

用户在 TodoTree 页面内，通过右上角按钮打开类似 VS Code 的右侧 Agent 抽屉，用自然语言查询或修改当前完整的 TodoTree 数据。Agent 基于 Pi Agent。它应能处理现有 `AppData` 模型中的任务树、任务字段和标签，而不是只支持预先定义的“过期任务”命令。“找出所有已过期任务，然后删除”是通用能力的一个验收场景；其中“过期”已确认为未完成且截止日期早于用户本地今天，今天到期和无日期不算过期。为了不破坏备份兼容性，`formatVersion` 和现有模型之外的扩展字段不由 Agent 修改；这不是任意 JSON 文件编辑器。

本轮仍以浏览器中的 `AppData` 为唯一任务数据源，保留现有本地保存与 JSON 导入导出。Cloudflare R2 将来用于多设备同步，本轮不接入，也不为它引入账号、远端数据副本或同步流程。

## 方案选择

采用“读取完整 `AppData` + 提出带基版标识的 RFC 6902 JSON Patch”。这给 Agent 通用的数据操作能力，同时使每次变更只描述实际修改。比较过的其他方案：

- 输出一份完整的新 `AppData`：接口简单，但每轮重写整棵树会增加模型输出量，遗漏无关节点也会成为删除。
- 仅暴露新增、修改、删除等固定业务工具：容易限制操作，却会把自然语言能力绑在预设命令上，不能满足管理整体 JSON 的目标。

Patch 只是 Agent 的提案格式；它不改变导入导出的 `formatVersion: 1` 文件格式，也不作为未来 R2 的存储格式。任务数据仍以完整快照持久化。

## 页面与交互

导航栏右上角提供“Agent”按钮。桌面端 Agent 与现有任务详情共用右侧面板位置；在两者之间切换时保留任务选择、Flow 视口、当前会话和未发送草稿。作为适配小屏的设计选择，移动端以全屏面板呈现同一流程，关闭后回到原视图。

抽屉有消息列表、运行与错误状态、输入框。只读问题直接以对话回答。写入请求产生一份待审阅提案：先显示新增、修改、移动、删除的数量，再按稳定任务 ID 和完整路径展示任务/标签的旧值与新值。删除父任务时列明整个子树的实际删除范围，分别显示直接命中与连带删除的数量；原始 Patch 和 JSON 差异放在可展开的技术详情中。确认区重复显示实际影响总数；若有删除，主按钮写明“删除 N 项并应用变更”，否则写“应用变更”。用户可应用或拒绝；聊天回复本身不写入数据。一次只保留一份待审阅提案，新的写入请求要先处理或拒绝旧提案。

首次向模型发送任务数据前，抽屉明确告知数据会经模型代理发送给所配置的模型服务。Pi 的对话记录和待审阅提案只保留在当前浏览器标签页的内存中；关闭再打开抽屉保留，刷新页面后清空，不进入 `AppData` 和 JSON 备份。这些保留规则是本规格的设计选择，不是需求方另行提出的存储要求。

## Pi 与数据边界

浏览器运行 `@earendil-works/pi-agent-core` 的 Agent 循环。仅提供两个应用工具：`read_app_data` 返回当前完整 `AppData` 及基版标识；`propose_app_data_patch` 接收基版标识和 RFC 6902 操作数组，生成提案。不给 Pi 文件、Shell、网络或直接保存 JSON 的工具。模型回复可解释提案，但不能绕过提案提交。

本轮在现有 pnpm workspace 中新增一个基于 **Fastify** 的 Node.js 22.19+ 后端应用。它只负责 Agent 模型代理与 Web 静态资源：开发时由 Vite 同源转发 API，构建后由 Fastify 配合 `@fastify/static` 提供 Web 产物，并提供 `/api/agent-config`、`/api/stream`。Fastify 原生支持 TypeScript 类型与流式响应，因此 SSE 不另建一层 HTTP 框架。`agent-config` 只返回模型元数据，不返回密钥。服务端通过 `TODOTREE_AGENT_PROVIDER`、`TODOTREE_AGENT_MODEL` 和相应供应商的服务端密钥环境变量配置一个 Pi 支持的模型；缺失配置时抽屉显示不可用。`/api/stream` 实现 Pi `streamProxy` 所需的 Bearer 请求和 SSE 事件协议，只接受服务端选定的模型及受限请求体，不接受浏览器指定的任意供应商地址。服务端不保存任务 JSON 或 Pi 会话。

本轮支持本机或已有外层访问控制的私人部署：本机进程只监听 loopback；代理协议中的浏览器令牌不被当作公网身份认证。未接入外层认证和请求限额的公网部署不属于本轮支持范围。模型密钥只留在服务端。Pi 当前包要求 Node.js 22.19 及以上，实施时统一项目的开发与构建运行时要求。

## 提案校验与提交

`propose_app_data_patch` 在当前快照的副本上应用 Patch。使用维护良好的现有 JSON Patch 库，并检查它的类型、不可变应用、路径验证和失败行为；不自行实现 RFC 6902。提案只可修改 `/todos` 和 `/tags` 中已知的任务、标签字段及其嵌套数组，不能替换根对象、整段替换 `/todos` 或 `/tags`、修改 `formatVersion` 或引入未知字段。拒绝无效路径、原型属性路径及失败的 `test` 操作。每份提案绑定读取时的完整快照；基版不一致时绝不按旧数组索引应用。`test` 可作为局部前置条件，但不代替基版核对和实际差异审阅。

计算提案后的完整 `AppData`，沿用并补强当前校验，确保任务和标签的已知字段形状、唯一 ID、标签引用、日期、评分和父节点完成状态合法；现有任务与标签的 ID 不可改，新增 ID 必须唯一，新建或改名后的标题不可只含空白。导入数据中原先存在的额外字段保持原样，Agent 不得增改它们。提案预览根据实际前后快照计算，不能仅转述模型的自然语言说明。若无法完整展示变更，提案不可应用。

点击应用时，再以最新 `AppData` 比对提案基版并重算、重验结果。基版已变化则停止应用、保留对话并提示重新生成，不自动合并到新数据。基版未变时，通过与现有 700 毫秒防抖保存共用的提交入口，取消待写的旧快照并先同步写入本地存储；写入失败则保留原状态并报错。写入成功后更新保存引用、一次更新 React 状态，图表和列表随之刷新；不存在“部分节点已删除”的中间状态。拒绝提案、取消确认和只读请求都不改变数据。若启动时 `loadAppData` 报错，Agent 的读取与写入均禁用，直到用户通过现有恢复流程重新载入有效数据，避免把错误回退的空树覆盖到原始存储。

应用成功后保留上一份完整快照，提供“撤销本次 Agent 变更”。撤销只在当前标签页未刷新、且成功应用后没有任何其他数据编辑时可用；否则立即隐藏。撤销同样先同步保存旧快照，成功后再更新界面；失败则维持当前数据并报错。这是本轮针对 Agent 写入的单步恢复，不改变普通编辑的撤销规则。

## 错误与限制

模型或网络失败时保留用户输入和当前数据；可重试，不重复提交。无效 Patch 返回具体原因供 Agent 修正，但不会写入。提案过大、数据格式不合法或无法解释影响范围时阻止应用。首版不提供自动执行、后台定时任务、跨页面刷新保存对话、外部系统工具、R2 同步或多用户共享。

## 验收

1. 通用读：Agent 能回答整份任务树与标签的查询，且数据不改变。
2. 通用写：覆盖批量新增任务、修改字段、移动任务、删除任务/子树、修改标签；每种操作都有与实际结果一致的差异预览，确认后刷新页面仍保留。
3. 示例指令“找出所有已过期任务，然后删除”：用已确认的过期口径核对整棵树，提案必须完整列出所有匹配任务的 ID、标题、路径和截止日期。若匹配父任务，删除它会连带删除整个子树；预览分别统计匹配任务和未匹配但会连带删除的后代，并显示实际删除集合。该规则由通用 JSON 与 Patch 能力完成，不新增“过期删除”专用工具。
4. 取消、拒绝、无效 Patch、基版变化、模型失败、本地读取或保存失败都不改变 `AppData`；错误可见且不产生部分写入。成功应用后的单步撤销仅在说明的范围内恢复原快照。
5. Agent 抽屉与任务详情切换不丢失选中任务和 Flow 视口；移动端可完成同一审阅与确认流程。

## 代码边界

以现有 `App.tsx` 的 `AppData` 为唯一权威状态，复用 `storage.ts` 的保存和校验入口；将 Agent 会话、Patch 提案校验/差异计算、抽屉 UI 分别放在前端职责明确的模块中。Fastify 后端单独置于 `apps/api`，仅实现模型配置、Pi 代理和静态资源服务，不复制任务数据状态。JSON 导入导出仍使用完整 `AppData`；本轮不增加云存储适配层。
