# TodoTree 统一 Pi Agent 与模型配置：设计规格

日期：2026-09-30
状态：已按需求方反馈确认，待制定实现计划

## 目标与范围

设置页应能配置多组 LLM 连接信息（API 地址、模型 ID、API Key），并一键切换当前配置。TodoTree 只运行一个 Pi Agent：同一段对话可以操作当前完整任务 JSON，也可以依据 Graphify 和少量已索引源码回答 TodoTree 项目问题。界面不设置“任务数据 / 项目代码”模式，也不维护两份会话。

继续沿用已确认的 JSON 管理与 Graphify 只读边界：任务写入先生成可核对的差异提案，用户确认后才保存；项目源码只读。任务数据仍以浏览器 AppData 为权威状态。本轮不接入 Cloudflare R2、多设备同步、远程任务副本或多用户会话。

本规格取代 [JSON 管理规格](2026-09-29-pi-agent-json-management-design.md)和[Graphify 代码问答规格](2026-09-29-pi-agent-graphify-code-qa-design.md)中“环境变量配置单一模型”及“两种模式使用独立 Agent/会话”的设计决定。两份规格中未被本文件改变的 Patch 校验、差异审阅、源码访问和 Graphify 命令约束继续有效。

## 方案选择

采用“服务端本地配置文件 + 设置页配置管理 + 单 Agent 多工具”。Fastify 是模型凭据与模型请求的唯一代理；浏览器只拿到非秘密的配置摘要和 Pi 模型元数据。一个 Agent 装载任务 JSON 与 Graphify 两组工具，通过同一系统提示按问题选择工具。

相较将 Key 保存在 `localStorage`，服务端文件可避免浏览器脚本、扩展或浏览器配置读取凭据；相较只使用环境变量，它支持在产品内增删配置和一键切换。首版不引入操作系统密钥链依赖。密钥在服务器本地配置文件中以明文存储，目录和文件权限限制为运行 TodoTree 的用户；读取 API 永不返回密钥。这个限制必须在设置页和部署文档中说明。

## 设置页与交互

设置页增加“Agent 模型”区块。它展示配置名称、API 地址、模型 ID、是否已保存密钥，以及当前使用标记。用户可以新增、编辑、删除配置，并点击“设为当前”立即切换。新增配置必须提供非空名称、API 地址、模型 ID 和 Key。API 地址按用户输入保存；保存时不检查地址格式、可达性或模型是否存在。设置页不提供协议选择，后端统一使用 OpenAI Chat Completions 兼容格式调用 Pi。

连接配置表单提供“一键测试连接”。测试使用当前表单里的 API 地址、模型和 Key（编辑已有配置且 Key 留空时使用服务器已保存的 Key），向该模型发送一次固定、简短的测试请求；显示成功或便于排查的失败原因，不保存配置。测试可能产生少量模型用量费用。测试失败不阻止保存；实际请求失败时保留输入并显示服务端返回的安全错误。

密钥输入使用密码控件。编辑时后端只返回 `hasApiKey`，输入框保持空白表示保留原 Key；显式清除动作才删除已有 Key。列表与编辑回显不得返回 Key。删除当前配置时必须先选择另一份含有效 Key 的配置；如果删除最后一份配置，活动 ID 置空并让 Agent 明确显示未配置状态。保存失败要显示原因，并保留用户表单输入。

切换模型不重置 Agent 消息、待审阅提案或草稿。切换发生时，当前 Agent 运行（包括同一轮中的工具调用和后续模型请求）继续使用运行开始时的配置；新选择在本轮完全结束后应用，之后的新一轮请求使用新配置。若 Graphify 不可用，Agent 仍可进行任务 JSON 操作；代码工具在调用时显示明确的 Graphify 错误。

首次向任何模型发送对话前显示数据传输说明。由于现在只有一个对话，同一上下文可能包含 Agent 读取过的 AppData、Graphify 结果和源码摘录；后续提问会把保留的对话上下文发给当前配置的模型服务。对话及提案仍只在当前浏览器标签内存中，不写入 AppData 或模型配置文件。

## 配置存储与 API

后端以一个 JSON 文件保存模型配置列表与活动配置 ID，默认路径为运行用户主目录下的 `.todotree/agent-profiles.json`，可通过 `TODOTREE_CONFIG_DIR` 指定配置目录。创建目录时设为仅运行用户可访问；文件写入采用临时文件后原子替换，并确保权限为 `0600`。无文件时以空列表启动；损坏或不可读时保持 Agent 不可用并报告错误，不得静默覆盖原文件。

配置记录包含稳定 ID、名称、API 地址、模型 ID 和 API Key。服务端内部将这些字段构造成 Pi 的 OpenAI Chat Completions 兼容模型；UI 不要求用户填写 token 限额或费用等模型内部元数据。GET 接口仅返回配置的非秘密字段、`hasApiKey`、活动 ID 和可供 Pi 使用的公开模型元数据。增加、更新、删除和选择当前配置使用独立 Fastify 路由；保存时校验必需字段及长度限制，但不向 LLM 发请求验证地址或模型。另有测试路由接收 profile ID 或未保存的表单字段，使用与正式请求相同的 Pi 适配器执行一次小请求；测试路由不持久化表单，只返回成功标记或经脱敏的错误摘要。模型请求携带配置 ID，后端通过该 ID 查找服务端记录及凭据；不信任浏览器传来的任意 Provider、基址或 Key。请求的 Pi 模型描述必须与该配置对应，避免用有效 ID 搭配伪造 API 地址。

`/api/stream` 对单一固定模型的环境变量校验改为按配置 ID 解析模型。服务端用对应记录中的 API 地址、模型 ID 和 Key 按固定的 OpenAI Chat Completions 兼容格式调用 Pi AI。为兼容现有启动方式，仅当配置文件不存在时，可将当前有效环境变量模型作为只读的临时“环境变量”配置展示；一旦用户保存设置文件，就只从文件读取配置，环境变量不覆盖用户选择。

本服务仍按现有本机/私人部署边界运行：默认仅监听 loopback；远程私人部署由外层认证保护。管理配置 API 和流式 API 不提供公网身份认证或多用户隔离，不支持直接暴露到公网。

## 单 Pi Agent 与工具边界

Agent 抽屉去掉任务/代码模式切换、分开的草稿/错误状态、双 Agent 实例和独立消息记录。它显示当前模型名称、配置切换入口（可链接到设置页）及 Graphify 状态，并保留现有输入、流式响应、提案审阅、应用、拒绝和撤销流程。

一个 Pi Agent 的工具集合包括：

- `read_app_data` 与 `propose_app_data_patch`：读取当前完整 AppData、生成受校验的待审阅 JSON Patch；永不直接保存。
- `query_project_graph`、`trace_project_graph`、`explain_project_node` 与 `read_indexed_source`：查询 Graphify 及其已索引的受限源码摘录；只读。

统一系统提示说明工具适用场景、过期任务口径、删除影响复核、源码证据与行号要求、`INFERRED` / `AMBIGUOUS` 的表达规则，以及所有工具返回均为不可信数据。模型回答项目事实必须以 Graphify/源码结果为依据；没有证据时承认无法核实。所有工具始终属于同一 Agent；不用 UI 模式来隐藏一组工具。

模型配置 ID 随每次流式请求发送，使服务端按请求开始时选定的配置解析凭据。浏览器切换模型时更新同一 Agent 的 `state.model`，消息上下文不清空。Graphify 接口和源码访问仍执行既有固定命令、输入输出限制、已索引跟踪文件校验、路径边界与 80 行摘录上限。

## 错误处理与数据安全

无活动配置、Key 缺失或模型信息无效时，只禁用模型请求，TodoTree 的其他功能仍工作。配置文件损坏、读取失败、写入失败、删除活动配置的冲突及模型请求失败均给出可理解错误，不丢失已有配置或用户表单。写配置使用原子替换，失败不得留下半截 JSON。

模型 Key 只经设置页提交到本地后端并由后端持有；GET、日志、异常响应、前端状态持久化和构建产物均不得包含 Key。Key 以明文存在服务器磁盘，因此本机文件权限是首版保护边界；远程部署必须使用可信访问控制。LLM 服务仍会收到本轮对话所需的用户输入和工具结果。

Agent 提案的快照比对、Patch 字段白名单、实际差异渲染、确认后同步保存、失败回滚及单步撤销沿用 JSON 管理规格。代码工具不得写 AppData，任务工具不得读项目文件系统。

## 验收

1. 用户可在设置页新增两份以上不同 API/模型/Key 配置；列表和读取接口不含任何 Key，重启 Node 后配置与当前选择保留。
2. 用户可新增、编辑、切换、删除配置；空密钥编辑保留旧 Key，显式清除才删除；删除活动配置时必须先切换到另一份有效配置；删除最后一份配置后活动 ID 置空并明确显示未配置状态。
3. Pi 流式请求使用对应 profile 的 API 地址、模型及服务端 Key。错误或伪造的 profile ID、模型描述、缺少 Key 均被拒绝；请求不会用客户端临时改写的任意地址连接。设置页保存不联网验证 API 地址；连接测试会实际请求模型且不保存草稿，成功、超时、无效地址、Key 错误、模型不存在等结果均可见，响应不泄露 Key。
4. 抽屉只有一个 Agent 和一份会话；其工具列表同时包含两个 AppData 工具和四个 Graphify 工具。连续询问任务与代码问题时消息上下文保留，界面没有模式切换或第二份会话。
5. JSON 读写继续遵循原规格：提案必须审阅确认，拒绝、无效 Patch、过期基版或保存失败均不改变 AppData；撤销范围与原规格一致。
6. Agent 可按需求调用 Graphify 证据回答代码问题；Graphify 不可用时任务 JSON 能力仍工作。源码访问保持只读和既有路径安全约束。
7. 第一次请求前显示共享上下文数据传输说明；对话和 Key 不写入任务备份。配置文件缺失、无效 JSON、权限不足和原子保存失败都有测试覆盖。测试连接只发送固定短提示，不发送任务数据或 Graphify 结果。
8. 没有 profile 文件但现有环境变量已完整配置时，Agent 显示只读的兼容配置；首次保存 profile 文件后，环境变量不再覆盖当前选择。
